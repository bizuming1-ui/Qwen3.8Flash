# 界面1：多设备生产记录

按照参考图片制作的网页，使用网址或右上角二维码在多台设备上打开同一个界面。五个字段由用户填写，修改会自动保存，并通过服务器推送实时同步，无需手动刷新。点击**确认**后，“当前生产数”直接替换为提交时“现在”的数字（不是累加），并清空“现在”。并发确认时，同一轮数字只会被确认一次；其他设备的过期输入不会把已清空的数字写回来。

## 启动

需要 Node.js 18 或更新版本：

```sh
npm ci
npm start
```

服务默认监听所有网络接口的 3000 端口。可使用 `PORT=8080 npm start` 修改端口。服务器的本机浏览器可打开 `http://localhost:3000/`；其他设备需要打开**它们也能访问到的地址**，例如同一局域网内的 `http://服务器局域网IP:3000/`，或者已部署网站的 HTTPS 网址。二维码始终指向当前浏览器打开的页面地址，因此如果用 `localhost` 打开，扫码后的其他设备会指向它们自己的 localhost，不能连接到服务器；请先用局域网 IP 或公开网址打开，再扫码。局域网访问可能需要放行防火墙。服务必须持续运行，GitHub 仓库本身不会自动托管网站。

所有连接到**同一个服务器实例**的设备共享一份数据。服务重启后数据保存在 `data/state.json`，可通过 `DATA_FILE` 环境变量指定其他持久化路径。备份此文件可保留记录；部署在临时文件系统的平台时需配置持久化存储。该实现为单进程、单实例设计，不能通过启动多个互不共享数据的实例进行横向扩展。反向代理需支持长连接 / Server-Sent Events，且关闭响应缓冲。

## 数据与安全

数字字段接受 0–9 的非负整数，最多 40 位；生产单和产品最多 120 个字符。修改后自动保存，提交前请确认网络连接正常。多设备同时修改同一普通字段时，以服务器最后收到的修改为准；确认操作会原子地替换当前生产数并清空现在。服务器端采用原子文件替换保存数据，发生保存错误时不会向其他设备广播未保存的状态。

本项目没有登录、访问控制或传输加密；知道网址并能访问服务的人都可以查看和修改数据。不要直接暴露到公共互联网或用于敏感数据；需要公网使用时，请在可信的 HTTPS 反向代理后增加身份验证和访问控制。
