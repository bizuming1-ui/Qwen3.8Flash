# 界面1

按照参考图片制作的黑白生产界面。多个浏览器打开同一个服务地址后，看到并编辑的是**同一组数据**；右上角二维码包含该界面的分享地址。电脑使用接近原图的布局，手机使用适合窄屏操作的布局。

## 操作规则

- “生产单”“产品”“生产总数”“当前生产数”“现在”均可手动填写，输入后自动保存并推送到其他在线设备，不需要按刷新键。
- 在“现在”输入数字并点击“确认”：**当前生产数直接变成刚输入的数字，“现在”清零并显示 `0`**。例如当前生产数为 `99`、现在为 `12`，确认后当前生产数是 `12`、现在是 `0`，不会变成 `111`。
- 确认时复制数字原文，不用浮点数计算，因此长数字、前导零和小数位不会被舍入。例如 `00012.50` 会原样显示。支持正负号和小数；空值、空格、千分位逗号及科学计数法不能用于确认。每个字段最长 256 个 JavaScript 字符单位。
- 不同设备同时编辑不同字段时各自保存；同时修改同一字段时，旧版本不会悄悄覆盖新值。发生冲突时，页面保留本地草稿并提示重新编辑；电脑上也可按 `Esc` 放弃冲突草稿、使用最新值。
- 网络断开时页面会提示并自动重连，未保存的输入只保留在当前页面内，连接恢复后会尝试保存。**断网期间关闭或重载页面，尚未保存的输入可能丢失。**确认请求会使用唯一编号重试，避免重试时清空其他设备之后输入的新数字。

## 本地启动

需要 Node.js **22.17.0 或更新版本**（推荐 Node.js 24）。在项目目录执行：

```bash
npm ci --omit=dev
npm start
```

打开 `http://localhost:3000/`。默认监听 `0.0.0.0:3000`；Node 22 可能显示 `node:sqlite` 的实验性功能提示，这不是运行错误。停止服务使用 `Ctrl+C`。

### 让其他设备访问

1. 手机与电脑处于同一局域网，并确保电脑防火墙允许访问服务端口。
2. 用电脑的局域网地址打开页面，例如 `http://192.168.1.10:3000/`；其他设备可以输入这个地址，或扫描页面右上角的二维码。
3. 如果从 `localhost` 打开，程序会尝试选择本机的局域网 IPv4 地址生成二维码。电脑有多张网卡时自动选择的地址可能不对，或者无法检测到地址；可指定实际可达的地址：

```bash
PUBLIC_URL=http://192.168.1.10:3000 npm start
```

Windows PowerShell 的写法：

```powershell
$env:PUBLIC_URL = "http://192.168.1.10:3000"
npm start
```

`PUBLIC_URL` 仅指定二维码内容，**不会自动把服务发布到公网**。要跨互联网访问，必须把本服务部署到可访问的服务器并配置域名、HTTPS 和网络规则。页面通过公网或预览地址访问时，默认使用当前浏览器地址生成二维码；鼠标悬停在二维码上也可以查看分享地址。临时预览只在预览环境和服务保持运行时可用，不是永久托管。

## 配置与数据

| 环境变量 | 默认值 | 作用 |
| --- | --- | --- |
| `PORT` | `3000` | HTTP 端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `DATA_DIR` | `data` | SQLite 数据目录 |
| `PUBLIC_URL` | 未设置 | 二维码使用的完整 HTTP(S) 根地址，例如 `https://example.com`；不支持路径、查询参数或账号密码 |

数据存储在 `DATA_DIR/interface.sqlite` 中，数据库文件已加入 `.gitignore`，不会随代码上传到 GitHub。服务器重启后会恢复已保存的数据。生产环境应将 `DATA_DIR` 放在持久化磁盘上，并在停止服务后备份整个数据目录（包括可能存在的 SQLite WAL 文件）。临时沙盒或容器被销毁时，未挂载到持久化存储的数据可能丢失。

本版本**没有登录、权限或加密功能**：任何能访问地址或二维码的人都可以查看和修改同一组数据。不要直接在公开网络中放置敏感生产信息；正式使用前应在网关或反向代理处增加访问控制、HTTPS 和网络限制。一个服务实例只维护一组共享数据，不提供独立工单房间或历史记录。

## 部署注意事项

- 使用一个 Node 进程提供这组界面；当前实时广播只在该进程内进行，不支持把多个工作进程或多个服务器直接挂在负载均衡器后面。扩容需要额外的跨进程消息机制和共享持久化存储。
- 反向代理应将站点**根路径**转发到本服务，并关闭事件流缓冲。示例片段：

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_read_timeout 1h;
}
```

- 浏览器使用同源相对 API 地址，不会要求其他设备访问其自己的 `localhost`。实时同步采用服务器发送事件（SSE），常规输入在约 120 毫秒的防抖后保存并推送；实际延迟取决于网络、服务器和代理。网络恢复后自动重新订阅并接收最新快照。
- HTML/CSS 负责参考图布局，浏览器 JavaScript 负责交互，Node.js 负责长连接和请求，SQLite/SQL 负责原子保存。对这个主要受网络和磁盘影响的小型系统，机械地混用更多语言并不会自动提高性能。

## 测试

```bash
npm ci
npm test              # 服务端、并发、确认、持久化、二维码接口
npm run test:browser  # Linux x64 上的真实 Chromium 多设备与二维码识别测试
npm run test:all
```

浏览器测试使用项目开发依赖中的无头 Chromium，需要 Linux x64 及 `tar`；常规服务端测试不依赖浏览器。测试覆盖多设备自动同步、移动布局、真实二维码解码、同字段冲突、断网重连、服务重启以及确认响应丢失后的安全重试。
